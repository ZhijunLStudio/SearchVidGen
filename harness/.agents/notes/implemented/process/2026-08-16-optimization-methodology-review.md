# Agent Note: 优化方法论回顾——什么模式产出了最高价值

Status: implemented

## Problem

42 轮持续优化的收益分布高度不均：少数模式产出了绝大部分价值，若干轮次
是低收益维护。把这些模式显式化，为未来轮次（与后续维护者）提供
"下一轮该做什么"的判断依据。

## Decision

高价值模式排序（按实际产出）：

1. **审计驱动修复**（E11/E14/E18/E20/E32/E36）：静默行为审计、笔记-代码
   一致性审计、真实数据账本审计——平均每轮发现 1-2 个真 bug（含
   fl2va 条件化静默失效、画布静默回落、提升规则死代码、路径双重拼接）。
   这是收益密度最高的轮型。
2. **范式缺口对照**（rounds 1-10）：以 DSH 原则表逐条找缺口（事件溯源/
   不变量/声明目录/孪生适配器），每个缺口落地即带测试与笔记。
3. **真实数据验收**（E16-E38）：机制交付后用真实运行/真实数据走一遍——
   "单测通过≠在真实分布上工作"多次应验（E14/E32/E36）。
4. **消融与因果**（E24/E26/E35/E37/E38）：控制变量 + 诚实负结果——
   把"感觉有效"变成"±量级"。
5. 低收益但必要：维护纪律（死代码/门禁/文档计数）——占轮次多、
   单轮价值小，防熵增。

反模式（已记录避免）：管道吞 exit code（E29）、绝对路径测试绕过 bug
形态（E36）、从 manifest 回读配置（E11）、把解析修复收益记到上层机制
账上（E26）。

## Alternatives considered

- **只做功能不做审计**：否决。7+ 个真 bug 全部来自审计轮；
  审计是最高 ROI 的轮型。

## Consequences

- 未来轮次的默认议程：①API key 到位即跑 H3 对比（唯一大实验）；
  ②周期审计（静默行为/笔记同步/真实数据账本）；③新模型接入时
  用孪生思维找 seam 缺口。
- 本笔记是"持续优化"目标的方法论锚点：每轮开始先问"这轮是审计、
  范式对照、真实验收、还是消融"。
