# Agent Note: mypy 类型门禁落地（22 处问题含 3 个真健壮性缺陷）

Status: implemented

## Problem

代码全量带注解但从无类型检查（工程基线笔记把 mypy 记为"未来轮次评估"）。
本轮评估：mypy 首跑 25 处报错，其中至少 3 处是真实健壮性缺陷——
注解的存在不产生价值，类型门禁才产生价值。

## Decision

1. **mypy 门禁**（ignore_missing_imports，34 文件 0 问题）：
   - 真缺陷修复：①OpenAI 响应 `message.content`/`usage` 可能为 None
     （判空/默认值，此前会 AttributeError）；②minimax API 分支的
     `r` 变量遮蔽（refs 循环变量与 Response 同名，可读性陷阱）；
     ③`inspect.signature(obj.__init__)` → `signature(obj)`（子类
     __init__ 覆盖时不健全）。
   - 类型卫生：dataclass aliases Optional、重复注解、变量遮蔽
     （td/judges）、cache 键类型、None 过滤。
2. pyproject 增加 [tool.mypy] 配置；RUNBOOK 增加命令。
3. **发布前全检跑齐**：mypy 0 问题 + ruff 0 问题 + 132 测试（core 93%）
   + doctor --all（15 run，6 条为 8-15 旧布局提示）+ regress 4 任务
   ✅ 一致 + leaderboard --all ✓——一套命令即可确认仓库健康。

## Alternatives considered

- **check_untyped_defs 全开**：否决。CLI/脚本层的 untyped 函数体收益低；
  当前 0 问题的门禁已覆盖核心类型契约。
- **types-requests/types-PyYAML 全量 stub**：否决。ignore_missing_imports
  下 0 问题已达成；引入 stub 依赖换取的第三方类型精确度当前不值得。

## Consequences

- 类型契约纳入健康清单：改动核心模块后 `mypy vidharness/` 必须 0 问题。
- 3 个真缺陷在它们触发前被移除（None 崩溃路径、变量遮蔽）。
- 完整健康门禁 = pytest(132) + mypy + ruff + doctor --all + vh regress。
