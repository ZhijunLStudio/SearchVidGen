# Agent Note: 裁判重复评测方差分解——确定性实证 + 跨代不可比警示（E42）

Status: implemented

## Problem

评测闭环是 harness 的护城河（E2），但裁判可靠性从未被量化：
E16/E23 的臂间方差无法区分"生成方差 vs 裁判方差"——如果裁判自身
随机，所有 A/B 的检出限都要打折扣。同时，老 run（8-14/8-15）的
评分与今日是否可比从未实证（E24 只覆盖了同代混用裁判的口径标注）。

## Decision

1. **scripts/judge_repeatability.py**：同视频同口径重复评测 N 次。
   裁判端点/参数/维度全部从 run 的 config.yaml 快照读取（E13 原则，
   零硬编码）；结果落为事件溯源实验（task=judge_repeat：events +
   manifest + artifacts/judge 原始输出 + summary 维度统计）。
2. **三个实验**（judge-qwen3.5-27b，temperature 0 + thinking off）：
   - seg01（本代高分视频）×5：10.0/10.0 sd=0，与原记录完全一致
     ——本代裁判对同视频的可复现性 ✓
   - 蓝屏合成视频 ×3：1.0/1.0 sd=0——低分端同样确定性，
     裁判在本代内有区分力（1.0 vs 10.0）✓
   - seg04（8-14 记录画面质量 5.0）×5：今日全部 10.0——
     **跨裁判代际不可比实证**（8-14 裁判是启用思考的旧版，
     维度集也不同，同名 adapter 不同模型代）
3. **Harness 修改**：旧布局推断标注从"judge.openai-compat（推断：
   旧布局未记录）"强化为"（推断：旧布局未记录，裁判版本未知，
   跨期不可比）"——把 E42 的跨代警示固化进 leaderboard/报告口径。

## Alternatives considered

- **用 bench 做臂间重复**：否决。需要生成 GPU 且 n≈10 才够（E38）；
  裁判侧分解不需要生成，纯 vLLM 调用即可把"生成方差 vs 裁判方差"
  切开。
- **录播回放旧裁判**：不可能。旧服务已换代，旧模型的输出风格
  （思考链）已无法复现。

## Consequences

- **方差分解结论**：固定帧输入下裁判 sd=0（temperature 0 确定性 +
  抽帧时间点固定）→ E16/E23 的臂间方差全部来自生成与抽帧内容差异，
  不是裁判噪声。A/B 设计无需重复评测，只需重复生成。
- **裁判换代的验收标准**：未来换裁判模型时重跑本脚本——旧视频应有
  合理的新分布，且同视频重复 sd 仍应为 0。
- **跨期比较纪律**：8-16 前的评分与今日不可比（E8/E10 等旧结论只在
  其代内成立）；leaderboard 口径已带警示。
- **成本口径备注**：裁判 GPU 时间不计入 ledger（judge 能力无 backend
  声明）——共享 vLLM 服务的计价基准与生成卡不同，保持不计，显式记录
  此简化而非静默。
- 账本 +3 judge_repeat 实验（纯裁判，0 生成 GPU 时）。
