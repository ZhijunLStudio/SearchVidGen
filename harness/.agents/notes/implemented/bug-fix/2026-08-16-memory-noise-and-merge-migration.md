# Agent Note: 经验记忆噪声清洗与同键合并迁移（E32）

Status: implemented

## Problem

真实记忆审计（29 条生产数据）暴露三个问题：①**JSON 噪声**：7 条 complaint
是整段/多段 JSON（unparseable_feedback 的原文片段混入记忆），既不可读也
无法与同类文本聚类；②**基础设施噪声**：解析失败指令本身可能入记忆；
③**聚类粒度**：~20 条"叙事缺乏起承转合"的语义近重复因措辞不同而
规范化键不同，永不提升——E14 的提升机制在机制上正确、在数据上被噪声
与粒度卡死。

## Decision

1. `clean_feedback_text`（core/memory.py，单一正源；judge_loop 薄委托）：
   - 正则抽取首个 `{"<维度>": <分>, "feedback": "<文本>"}` 的内层文本
     （覆盖整体 JSON 与多对象拼接两种形态）；
   - "评分解析失败…"指令视为基础设施噪声 → 空串跳过。
2. **记忆加载迁移**：_load 时清洗 complaint + 键重算 + **同键合并**
   （count 累加、sources 截断、promoted 取或）+ 合并后按阈值补提升。
   真实迁移：29 条 → 0 残留 JSON、3 提升（备份 /tmp/memory.bak）。
3. 两个记忆写入点（stage_script / optimizer）先清洗后写入。

## Alternatives considered

- **语义聚类（LLM 嵌入）**：否决（本轮）。近重复聚类需要嵌入模型，
  引入新依赖与口径问题；正则在当前噪声形态下已解决可解决的部分，
  语义聚类记录为未来项（proposed 级）。
- **迁移只清洗不合并**：否决。同键合并是 E14 语义的补全——历史数据
  里存在同键散落条目时，合并才让阈值有意义。

## Consequences

- 记忆质量三层保障：写入清洗 + 加载迁移 + 同键合并提升。
- 语义近重复（文本不同）仍是已知缺口：待嵌入聚类（未来轮）。
- 迁移幂等：再次加载同一文件结果稳定。
