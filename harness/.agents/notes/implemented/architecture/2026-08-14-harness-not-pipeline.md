# Agent Note: 视频生成领域做的是 Harness 而不是流水线

Status: implemented

## Problem

2026 年的全模态模型（MiniMax H3 等）正把"脚本→图像→视频→TTS→字幕"的分离式流水线
**吸收进单次生成**（文字+参考 → 视频+原生音频，一次调用）。如果 VidHarness 仍以
"固定 N 步业务流水线"为核心资产，每一个模型换代都会让流水线里的步骤被模型内化、
变成死代码。同时，模型换代周期（3-6 个月）远快于评测基准的积累周期。

## Decision

VidHarness 定位为**视频生成流水线的实验与评测 Harness**，对标 LLM 生态的
`lm-evaluation-harness`：适配器是更新单元，任务是评测目标，实验产出可复现证据。

"会被模型吸收"与"不会被模型替代"的分界线（2026-08 判断）：

| 会被模型吸收（不做厚） | 不会被模型替代（做厚，harness 的护城河） |
|---|---|
| 图像/一致性组件（IP-Adapter、InstantCharacter 类） | **评测层**：模型不会给自己做质检；生成越"一体化"，验证越稀缺 |
| 独立 TTS / 音效阶段 | **跨片段编排**：模型单次 ≤15s，30-60s 故事片的多段拼接与上下文携带是持久需求 |
| 字幕 ASR（自产旁白无需转写） | **跨段一致性验证**：跨调用的角色/场景延续性检查 |
| 固定 7 步业务流水线 | **实验与基准**：模型换代越快，统一评测/对比/成本统计越值钱 |

依据实验 E1：MiniMax H3 单次调用产出"视频+原生音频"，原 7 步流水线的图像/TTS/音效
阶段被模型内化。harness 因此只保留四个能力缝：生成/剧本/评测/转写。

## Alternatives considered

- **继续做厚业务流水线**：否决。模型每换代一次，被吸收的步骤就变成死代码；评测与
  跨段编排的缺口却没人补（它们永远不会被单次生成模型内化）。
- **纯评测基准（不编排）**：否决。单次生成上限（5-15s）决定了多段编排+上下文携带
  是长期需求；放弃编排等于放弃 30-60s 故事片的评测对象。
- **围绕单一模型做深度集成**：否决。模型换代 3-6 个月一轮，深度集成的高成本在换代时
  全部沉没；适配器模式让"换下一个全模态模型 = 新文件 + 一行注册"。

## Consequences

- harness 只保留生成/剧本/评测/转写四个能力缝，其余能力按需新增（见 seam 角色映射笔记）。
- README 的"为什么是 Harness"表是本决策的持续对照表；模型每吸收一块能力，
  应在表中移动一行并更新本笔记。
