# VidHarness 目标达成证据（2026-08-15）

> 目标：为 SearchVidGen 打造面向未来的视频生成流水线 Harness（模型适配器抽象 + 实验管理 +
> VLM 质量评测闭环），8 卡本机部署中等模型，用 DeepSeek V4-Flash API 端到端跑通
> 「搜索词→成片」，持续实验迭代，产出可运行代码与实验证据。

## 逐项证据

### 1. 模型适配器抽象 ✓
- `seams/`（4 个服务定义：生成/剧本/评测/转写）+ `providers/`（6 个实现）+ `consumers/`（6 个编排）
- 注册表 + 能力声明 + 校验 fail-loud；新模型 = 新适配器文件（已实证：同一 MediaGenerator 协议下
  fl2va/t2va/ref2va 三种工作流、int8/bf16 两种加载方式切换仅改 YAML）
- 降级链 `generator.fallback`：多提供者按序切换，产物标记 fallback_used

### 2. 实验管理 ✓
- manifest 全程记录（模型版本/参数/seed/耗时/API成本/GPU小时/重试）
- 产物缓存 + `--resume` 断点续跑（实测：崩溃后跳过已生成段直接续跑）
- `report` 命令多实验 HTML 对比 + `compare_chains.py` 策略对比

### 3. VLM 质量评测闭环 ✓
- Judge 协议 + 生成→评分→失败反馈重试（实测触发：段3/4 低分自动重生成）
- 逐段评测（指令一致/画面质量/音效相符）+ 跨段评测（一致性/叙事推进）+ 音频验证（ASR 转写比对）
- 可靠性审计 E9：33 次调用 100% 解析成功
- 音频验证实证：旁白朗读 4/4 段 ASR 转写与剧本重叠度 0.83-1.0

### 4. 8 卡本机部署中等模型 ✓
- MiniMax H3（2026-07 开源，33B 全模态）：196GB 权重下载，fl2va/t2va 双卡 bf16 + ref2va int8 单卡（38GB）
- Qwen3.5-27B（多模态裁判，vLLM 服务 GPU7）+ SenseVoice（音频验证，CPU）
- 全部推理链踩坑与解法落档（harness/README.md 踩坑记录 + RUNBOOK.md）

### 5. DeepSeek V4-Flash 端到端「搜索词→成片」✓
- 剧本规划 API（8.4s/次，$0.00008）→ H3 逐段生成（视频+原生音频）→ 评测闭环 → FFmpeg 拼接+字幕
- 3 部成片：程序员故事 32s（hard）、雨夜小猫 37.7s（hard）、雨夜小猫 37.7s（none）
- 第 4 部（ref 参考衔接）运行中

### 6. 持续实验迭代 ✓（E1-E9 落档于 harness/README.md）
- E2 思考型裁判 token 燃烧 → 修复与验证
- E3/E8 画面连续≠好剪辑：hard 叙事推进 1.0 vs none 10.0（量化证据）
- E5/E7 ref2va 显存攻坚 → int8 单卡方案（78GB→38GB）
- E4 成本实盘：单段 ~18min，一部片 GPU ≈ $1.6-2
